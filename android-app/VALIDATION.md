# 验证记录 · 0.2.0

目标平台为 Android 14+ / arm64。用户计划使用 vivo X Fold5 和荣耀 500；本次未连接这两款真机。

## 已完成

- Android APK 构建、8 项文字策略单元测试、Android Lint 通过。Lint 为 0 错误；仍有版本更新提示、中文界面国际化及图标资源等非阻断警告。
- Android 15 arm64 模拟器中运行 6 项设备检查，全部通过，0 跳过：首页按钮可见性与渲染、JNI 加载及无效路径异常、轻量模型直接 JNI 生成 JSON、损坏模型导入不覆盖现有文件、真实中文音频识别、增强模型同音错字纠正。
- 设备测试直接调用生成引擎，超时回退不能算模型测试成功。原生 C++ 在调试包中也开启 `-O3`。
- 实际增强模型用例：输入“师傅我在对面，传白衣服，你等我一下。”，输出通过检查，包含“对面”“穿白衣服”“等我”。
- 使用固定版本 SenseVoice 的公开中文音频（5.59 秒）验证识别；样本来源为模型维护者仓库的 `test_wavs/zh.wav`。
- APK 签名校验与 16 KB ZIP 对齐检查通过；确认 `minSdk=34`、`targetSdk=35`、`arm64-v8a`。
- 网页 `check:runtime` 与构建通过，模板受保护运行时未修改。仍有约 500 KB bundle 提示。

本次模拟器检查约 38.6 秒；其中轻量 AI 用例约 10.8 秒、增强纠错用例约 13.0 秒、语音用例约 2.4 秒。这些包含不同程度的冷加载与测试开销，不是手机性能承诺。主机上也验证过同一 C++ 引擎和模型。

## 已知边界

- 0.5B 模型可能精简不足，也可能改动语义。增强模型同样不保证正确。数字、否定词、常见“等我 / 接我 / 找我”等人物关系变化会触发原话回退；其他语义错误仍可能漏过检查。
- 一条合成语音的否定句在 ASR 阶段出现漏字，说明文字 AI 无法可靠恢复录音中已漏识的意思。应用始终先展示原话和可编辑结果，确认后才亮屏。
- 测试中模型由开发脚本导入已验证的文件。手机网络下载、系统文件选择器及实际麦克风收音仍需在目标手机验收。
- 页面图为安卓应用自身 View 渲染，不包含系统状态栏；见 `design/native-home.png`。

## 目标真机验收

- 首次授权、拒绝授权、系统麦克风开关关闭、其他应用占用麦克风。
- 噪声、不同距离、口音、人名 / 地名、数字与否定句的识别准确率。
- 断网识别与 AI 整理，连续使用的等待时间、内存、温度和电量。
- vivo X Fold5 外屏 / 内屏切换、展开状态与旋转；荣耀 500 默认 / 大字体。
- 模型下载中断后继续、本地文件导入、空间不足和覆盖更新。

可用 `scripts/run_device_smoke.py` 在专用测试设备重现模型验证；需要先构建 APK 并准备模型和 16 kHz 单声道 PCM 测试音频。该脚本会安装测试包并写入模型。
